# Технический отчет: Архитектура Wear OS Tiles

Данный отчет объясняет принципы работы «плиток» (Tiles) и причины, по которым предыдущие реализации виджета AIMalb были неэффективны.

## 1. Кто рисует виджет?
В отличие от обычного Android-приложения, где UI рисует само приложение в реальном времени, виджеты Wear OS работают по принципу **ProtoLayout**:
1. Приложение отправляет системе «чертеж» (Layout Blueprint).
2. Системная служба часов (Renderer) читает этот чертеж и **сама** отрисовывает его на экране.
3. Приложение в этот момент может быть полностью выключено.

## 2. Почему логотип был «маленьким и темным»?
- **Tinting (Тинтинг)**: Если иконка передается внутри компонента `Button`, система Wear OS автоматически применяет к ней фильтр «Primary Color». В темных темах это часто приводит к тому, что яркие неоновые цвета (как ваш бирюзовый) превращаются в тусклые или серые.
- **Безопасные зоны**: По умолчанию система резервирует место под иконку приложения сверху и отступы по краям. Использование стандартных шаблонов (`PrimaryLayout`) «зажимает» контент в центре, уменьшая его масштаб.
- **Решение**: Использовать `LayoutElementBuilders.Image` напрямую. Это отключает системные фильтры и позволяет картинке занять всё доступное пространство.

## 3. Проблема кеширования ресурсов
Система часов кеширует изображения виджетов для экономии батареи. Идентификатором кеша служит строка `resourcesVersion`.
- Если мы меняем код или файл картинки, но оставляем ту же версию ресурсов, часы **не будут** перерисовывать виджет. Они покажут старую картинку из памяти.
- Именно поэтому мы обязаны увеличивать это число при каждом визуальном изменении.

## 4. Почему не срабатывал запуск микрофона?
Переход из виджета в приложение осуществляется через `LaunchAction`.
- В Wear OS для передачи параметров (extras) используется строго определенный формат `AndroidBooleanExtra`.
- Если в `MainActivity` проверка этого параметра происходит раньше, чем инициализируется движок ассистента, команда теряется.
- **Решение**: Перенос проверки во внутренний цикл интерфейса (`LaunchedEffect`), который дожидается полной готовности приложения.

## 5. Именование APK и Android Studio
Android Studio (IDE) отслеживает установку приложения по жесткому пути к файлу.
- Любое изменение `archivesName` в Gradle «на лету» заставляет Студию искать файл там, где его нет.
- **Решение**: Использовать условие `android.injected.invoked.from.ide` для разделения имен файлов для разработки и для релиза.
